# Задание 4. Автотест формы входа на Selenium

Автотесты лежат в папке `autotests` в корне репозитория (там же страницы и общие настройки). Для этого задания: `autotests/tests/test_login.py`.

## Как устроено

- **Page Object.** Каждая страница портала это класс в `autotests/pages`: `BasePage` (общие действия и ожидания), `LoginPage` (поля входа, кнопка «Показать», сообщение об ошибке), `RegisterPage`, `HomePage` и страницы заявок. В тестах нет селекторов, только методы: `LoginPage.sign_in(login, password)`, `error_text()`.
- **Явные ожидания.** Все действия идут через `WebDriverWait` (`visible`, `clickable`, `wait_url_path`), `time.sleep` нигде не используется. Подсказку браузера у пустого поля читаю через `validationMessage`.
- **Скриншот при падении.** Хук в `conftest.py` сохраняет окно браузера в `autotests/failures` и печатает путь в отчёте pytest. Чтобы показать это, есть тест `test_demo_failure_makes_screenshot`: он специально ждёт неверный текст и помечен `demo_fail`, в обычный запуск не входит.
- **Независимость.** Каждому тесту нужен свой участник: фикстура `user` регистрирует его запросом с уникальным логином.

## Тесты формы входа (7 штук)

| Тест | Что проверяет |
|---|---|
| `test_successful_login_opens_my_applications` | верные данные: адрес `/applications`, в шапке логин |
| `test_wrong_password_shows_error` | неверный пароль: «Неверный логин или пароль», остаёмся на `/login` |
| `test_unknown_login_shows_same_error` | несуществующий логин: то же сообщение |
| `test_empty_fields_are_stopped_by_browser` | пустые поля: браузер не отправляет форму |
| `test_logout_shows_guest_header` | после выхода в шапке снова «Вход» |
| `test_guest_is_redirected_from_private_page` | гость на `/applications` попадает на `/login` с сообщением |
| `test_password_can_be_shown_and_hidden` | кнопка «Показать» меняет тип поля |

Запуск (портал должен работать на 8102):

```
cd autotests
pip install -r requirements.txt
python -m pytest tests/test_login.py -v
```

`HEADLESS=0` покажет окно браузера, `PORTAL_URL` задаёт другой адрес.

## Результаты

- Все 7 тестов проходят (`screens/01-автотесты-входа.png`).
- Тесты на найденные ошибки (`test_regression.py`: BR-01 логин в другом регистре, BR-02 пароль из пробелов, BR-06 заявка на прошедшее мероприятие) запускал на старой версии портала: три теста упали, и каждый оставил скриншот страницы (`screens/03-тесты-на-ошибки-до-исправлений.png`, `04`, `05`). После исправлений проходят все три (`02`). Значит тесты действительно ловят эти ошибки.
- Демонстрация падения: `screens/06-демо-падение-и-скриншот.png` (вывод pytest) и `07-скриншот-при-падении-демо.png` (снимок, который сохранил хук). Это снимок самого Selenium (без рамки окна).

Браузер только Chrome 156.0.8078.80 (Selenium 4.51, драйвер подбирает Selenium Manager). В Firefox и Edge автотесты не запускал.
