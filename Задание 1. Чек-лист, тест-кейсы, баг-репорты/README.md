## Тест-кейсы

Все пять выполнила в браузере на версии до исправлений, данные для входа тестовые.

**TC-01. Регистрация нового участника.** Предусловие: логин `natali_t1` свободен. Шаги: открыть `/register`; ввести логин `natali_t1`, пароль `Password123`, почту `natali.t1@mail.test`, телефон `8 900 111-22-33`; нажать «Зарегистрироваться». Ожидается: переход на главную, сообщение «Вы зарегистрированы», в шапке «Кабинет (natali_t1)». Фактически так и получилось. Статус: пройден (`tc01-1`, `tc01-2`).

**TC-02. Вход с неверным паролем.** Предусловие: участник `natali_t1` существует. Шаги: открыть `/login`; ввести логин `natali_t1` и пароль `Неверный1`; нажать «Войти». Ожидается: остаёмся на странице входа, красное сообщение «Неверный логин или пароль». Фактически так. Статус: пройден (`tc02`).

**TC-03. Подача заявки на мероприятие.** Предусловие: участник вошёл. Шаги: открыть «Тестирование: от чек-листа до CI»; нажать «Подать заявку»; выбрать помещение «Малый зал», оплату «Картой онлайн»; отправить. Ожидается: сообщение «Заявка отправлена», в «Моих заявках» карточка со статусом «новая». Фактически так. Статус: пройден (`tc03-1`, `tc03-2`).

**TC-04. Администратор меняет статус заявки.** Предусловие: заявка из TC-03 существует. Шаги: войти как `admin`; открыть панель, выбрать мероприятие в фильтре; у заявки выбрать «назначено», нажать «Сохранить». Ожидается: сообщение «Заявка №5: статус «назначено»», карточка с новым статусом. Фактически так. Статус: пройден (`tc04`).

**TC-05. Отзыв после завершения.** Предусловие: у участника `ivan_k` есть завершённая заявка на прошедшее мероприятие «Нейросети в школе: практика». Шаги: войти как `ivan_k`; в «Моих заявках» выбрать оценку 5, написать отзыв; отправить. Ожидается: «Спасибо за отзыв», в карточке «Ваш отзыв, 5 из 5». Фактически так. Статус: пройден (`tc05-1`, `tc05-2`).

## Баг-репорты

Девять дефектов нашла прогонами из заданий 1 и 3. Окружение у всех одно: Windows 11, Chrome 156.0.8078.80, Node.js 22.14.0, портал `4a86f35`. Все исправлены в портале (коммиты в `conf-express`: `ec4212b`, `dc25c82`, `0e6bd11`), после этого скрипты и автотесты прошли заново.

**BR-01. Логин в другом регистре считается свободным.** Серьёзность: средняя. Шаги: зарегистрироваться с логином `Ivan_K` (в базе есть `ivan_k`). Ожидается: «Такой логин уже занят». Фактически: регистрация прошла, в кабинете «Ivan_K» (`br01-принят-логин-Ivan_K.png`, проверка R-11). После исправления: ошибка под полем «Логин» (`br01-после-...`). Исправлен: уникальный индекс `COLLATE NOCASE` и поиск логина без учёта регистра.

**BR-02. Пароль из пробелов принимается.** Серьёзность: средняя. Шаги: зарегистрироваться с паролем из восьми пробелов. Ожидается: отказ. Фактически: код 302, аккаунт создан (R-15). Исправлен: пароль без непробельных символов отклоняется.

**BR-03. Почта без ограничения длины ломает страницу на телефоне.** Серьёзность: средняя. Шаги: зарегистрироваться с почтой из 120 символов `a` и открыть `/cabinet` на 390 px. Ожидается: почта до 254 символов, страница по ширине экрана. Фактически: почта принята, ширина страницы 1109 px вместо 390 (`br03-...png`, проверка R-22). Исправлен: максимум 254 символа.

**BR-04. Пароль длиннее 72 байт усекается.** Серьёзность: средняя. Шаги: зарегистрироваться с паролем из 72 букв `A` и слова `first`, потом войти с паролем из 72 `A` и слова `other`. Ожидается: вход невозможен. Фактически: вход выполнен, bcrypt учитывает только первые 72 байта (L-09). Исправлен: пароль больше 72 байт отклоняется при регистрации.

**BR-05. Слишком большой запрос даёт ошибку 500.** Серьёзность: низкая. Шаги: отправить POST на `/login` с телом 200 КБ. Ожидается: 413. Фактически: страница «Ошибка сервера» с кодом 500 (M-02). Исправлен: обработчик ошибок отдаёт код 4xx из ошибки. Первое исправление возвращало 413, но страница ошибки не рисовалась (в выводе тестов портала была ошибка `path is not defined`: запрос обрывался до подстановки пользователя в шаблоны), поэтому добавила значения по умолчанию и проверку текста страницы.

**BR-06. Заявка на прошедшее мероприятие принимается.** Серьёзность: высокая. Шаги: войти, открыть адрес `/applications/new?event=1` (мероприятие 18.09.2026), выбрать значения, отправить. Ожидается: заявки не принимаются. Фактически: «Заявка отправлена», в списке заявка на прошедшее мероприятие (`br06-1`, `br06-2`, проверка F-05). На странице мероприятия кнопки нет, но сервер не проверяла дату. Исправлен: проверка на сервере, ответ 422 (`br06-после-...`).

**BR-07. Заявку на будущее мероприятие можно завершить.** Серьёзность: средняя. Шаги: в панели выставить статус «завершено» заявке на мероприятие 26.11.2026. Ожидается: запрещено. Фактически: статус «завершено» (`br07-завершена-...png`, проверка F-08). Исправлен: завершить можно только после мероприятия.

**BR-08. Статус можно вернуть назад.** Серьёзность: низкая. Шаги: у заявки «назначено» выбрать «новая». Ожидается: порядок новая, назначено, завершено. Фактически: статус изменился (F-10). Исправлен: в списке остаются текущий и следующий статусы, сервер проверяет то же.

**BR-09. Личные страницы можно достать из кеша браузера.** Серьёзность: низкая. Шаги: проверить заголовки `/applications`, `/cabinet`, `/admin` под вошедшим пользователем. Ожидается: `Cache-Control: no-store`. Фактически: заголовка нет (F-18a-c). После выхода кнопка «Назад» может показать страницу из кеша. Исправлен: для вошедшего пользователя всегда `no-store`.
